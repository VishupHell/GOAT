# Паспорт проекта

## Общие сведения

**Название команды:** Медовый спас
**Название продукта:** КоЗа - управление командными задачами
**Коды участников:** `M1`(VishupHell), `M2`(Restmine20), `M3`(paket8d)
**Статус ранней калибровки:** `черновик`

## 1. Назначение

Продукт позволяет командам грамотно распределять задачи между ее участниками
и отслеживать прогресс их выполнения. 
Каждый участник команды может изменять статус своих задач и 
просматривать информацию о каждой созданной задаче.
## 2. Граница продукта

**В продукт входит:**

- регистрация и вход участников, объединение их в команду
- создание задачи участником команды: описание, назначение исполнителя из состава команды
- отправка результата исполнителем
- проверка результата автором: принятие задачи или возврат на доработку с комментарием
- просмотр списка задач и их текущего статуса участниками команды

**Внешнее окружение и внешние системы:**

Отсутствуют

**Команда сознательно не реализует:**

- Фронтенд часть системы
- Возможность интеграции продукта с внешними системами

## 4. Сквозные сценарии

### Сценарий 1. Постановка задачи

- **Участники:** пользователи A и B
- **Начальное условие:** есть команда X, участниками которой являются пользователи A и B
- **Основные действия:** участник A создает и настраивает задачу, назначает исполнителем участника B
- **Результат:** каждый участник команды, кроме A и B, стал посторонним для созданной задачи, участник B стал ее исполнителем, участник A - автором
- **Какие данные или состояние изменяются:** общий список задач для выполнения, у исполнителя она появляется в личном списке задач

### Сценарий 2. Выполнение задачи

- **Участники:** пользователи A и B
- **Начальное условие:** A и B - автор и исполнитель задачи X, а также участники команды Y
- **Основные действия:** исполнитель ставит статус задачи X "В работе", решает задачу, ставит статус "На согласовании", автор проверяет задачу, оставляет свой комментарий, ставит статус "На доработке" или "Завершена".
- **Результат:** изменение статуса задачи
- **Какие данные или состояние изменяются:** статус задачи

### Сценарий 3. Создание команды

- **Участники:** зарегистрированный пользователь
- **Начальное условие:** -
- **Основные действия:** пользователь создает команду, приглашает в нее других пользователей, выдает права администратора доверенным лицам
- **Результат:** создана новая команда, объединяющая всех приглашенных пользователей
- **Какие данные или состояние изменяются:** некоторые участники этой команды получают права администратора

## 5. Значимые данные и другие объекты

Назовите не менее двух содержательно различных классов данных или иных объектов. Для каждого укажите конкретные последствия возможного нарушения.

| Данные или объект | Для кого имеют значение | Последствия раскрытия | Последствия неправильного изменения, удаления или недоступности |
| --- | --- | --- | --- |
| Задача | автор, исполнитель, команда | посторонний узнает содержание рабочей задачи команды, включая, возможно, чувствительные рабочие подробности | исполнитель работает по искажённому или удалённому описанию, задача теряет смысл или выполняется неверно |
| Результат выполнения| исполнитель, автор | раскрытие может показать постороннему объём и качество проделанной работы или содержащиеся в результате сведения |подмена или удаление результата лишает автора возможности объективно оценить работу; создаётся ложное представление о выполнении |
| Статус и назначение задачи (кто исполнитель, кто принял решение) | автор, исполнитель, команда в целом | раскрытие менее критично само по себе, но в сочетании с другими данными показывает распределение нагрузки в команде | подмена статуса или исполнителя может оставить задачу без исполнения либо создать ложное впечатление, что она принята |
| Комментарии | любой участник команды| может содержать прямую оценку качества работы конкретного участника, не предназначенную для посторонних | потеря или искажение комментария лишает исполнителя информации о том, что нужно исправить, и удлиняет цикл доработки|

## 6. Компоненты и внешние взаимодействия

- **Клиент (веб-интерфейс):** экраны списка команды, списка задач с фильтром «мои задачи как автор» / «мои задачи как исполнитель», форма создания задачи, форма отправки результата, форма решения по проверке
- **Сервер (API):** серверная предметная логика — создание задачи, проверка прав автора/исполнителя, переходы статуса (назначена → на проверке → выполнена / на доработке)
- **Хранилище данных:** участники, команды и их состав, задачи, результаты, комментарии, история статусов
- **Компонент уведомлений (опционально):** оповещение исполнителя о новой задаче и автора о поступившем результате — при нехватке времени может быть заменён обновлением списка при заходе в приложение
- **Аутентификация:** вход участника, необходимый для определения, какие задачи и действия ему доступны

Основные взаимодействия: клиент обращается к серверу за списком задач и отправляет действия (создать/назначить/отправить результат/принять/вернуть); сервер проверяет права участника относительно конкретной задачи и записывает изменения в хранилище.

## 7. Откуда продукт получает данные

| Источник | Пример данных | Кто управляет источником | Как продукт использует данные |
| --- | --- | --- | --- |
| Форма создания задачи | название, описание, выбранный исполнитель | автор задачи | создаёт запись задачи, привязывает исполнителя, устанавливает статус «назначена» |
| Форма отправки результата | текст или ссылка на результат выполнения | исполнитель | сохраняет результат, переводит статус задачи в «на проверке» |
| Форма решения по проверке | принятие или возврат, комментарий при возврате | автор задачи | меняет статус задачи на «выполнена» или «на доработке», сохраняет комментарий |
| Данные входа/сессии | учётные данные, идентификатор участника | сам участник и система аутентификации | определяет, от чьего имени выполняется действие, и какие задачи и права участнику доступны |
| Состав команды | список участников команды | участник, создавший команду, или все её члены (в зависимости от решения команды разработки) | ограничивает круг возможных исполнителей и круг видимых задач |

## 8. Минимальное функциональное ядро

**Обязательные функции:**

- создание команды и добавление участников
- создание задачи автором с назначением исполнителя
- отправка результата исполнителем
- принятие результата автором или возврат на доработку с комментарием
- список задач, различающийся для автора и для исполнителя

**Функции, которые можно исключить при нехватке времени:**


- редактирование и удаление уже созданных задач
- уведомления о назначении и смене статуса
- история изменений статуса и комментариев за пределами последнего решения
- поиск и фильтрация задач по дополнительным критериям
- отдельный список задач без исполнителя
