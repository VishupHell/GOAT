## 1. Назначение

Продукт позволяет командам грамотно распределять задачи между ее участниками
и отслеживать прогресс их выполнения. 
Каждый участник команды может изменять статус своих задач и 
просматривать информацию о каждой созданной задаче.
## 2. Граница продукта

**В продукт входит:**

- регистрация и вход участников, объединение их в команду
- создание задачи администратором команды: описание, назначение исполнителя из состава команды
- проверка результата администратором: принятие задачи или возврат на доработку с комментарием
- просмотр списка задач и их текущего статуса участниками команды

**Внешнее окружение и внешние системы:**

Отсутствуют


**Команда сознательно не реализует:**
- Фронтенд часть системы
- Возможность интеграции продукта с внешними системами

## 3. Пользователи и доступные действия

| Пользователь или роль   | Кто это                                                                | Что может делать                                                                                                                                                                                                             | Что ему недоступно                                                                                                        |
|-------------------------|------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------|
| Обычный пользователь    | Авторизованный в системе пользователь, не состоящий ни в одной команде | Создавать команды (становясь ее администратором), принимать приглашения в команду от других пользователей                                                                                                                    | Не может просматривать/изменять/создавать/удалять никакие задачи, не может просматривать/изменять/удалять никакие команды |
| Участник команды X      | Пользователь, входящий в состав команды X                              | Просматривать задачи (содержимое, комментарии, исполнителя и статус) команды X                                                                                                                                               | Не может как-либо изменять/удалять задачи команды X                                                                       |
| Администратор команды X | Создатель команды X                                                    | То же, что и участник команды X + создавать задачи, изменять задачи (содержимое, комментарии, исполнителя и статус) этой команды, удалять участников из команды X, приглашать пользователей в эту команду, удалить команду X | Просматривать/изменять/удалять любую команду, кроме X                                                                     |
| Исполнитель задачи Y    | Участник команды X, назначенный исполнителем задачи Y                  | То же, что и участник команды X + изменять статус задачи Y                                                                                                                                                                   | Не может менять исполнителя и содержимое задачи Y                                                                         |

## 4. Сквозные сценарии

### Сценарий 1. Постановка задачи

- **Участники:** пользователи A и B
- **Начальное условие:** существует команда X и пользователь A (администратор команды X) и пользователь B (другой участник команды X)
- **Основные действия:** участник A создает и настраивает задачу Y, назначает исполнителем участника B
- **Результат:** создана задача Y, участник B стал ее исполнителем
- **Какие данные или состояние изменяются:** общий список задач для выполнения, у исполнителя она появляется в личном списке задач

### Сценарий 2. Выполнение задачи

- **Участники:** пользователь B
- **Начальное условие:** существует пользователь B (участник команды X) и задача Y, исполнителем которой является B
- **Основные действия:** исполнитель меняет статусы задачи Y по мере выполнения
- **Результат:** изменение статуса задачи
- **Какие данные или состояние изменяются:** статус задачи

### Сценарий 3. Создание команды

- **Участники:** зарегистрированный пользователь W
- **Начальное условие:** существует пользователь W
- **Основные действия:** пользователь W создает команду X, приглашает в нее пользователей B1, B2, ..., Bn
- **Результат:** создана новая команда X, пользователь W стал ее администратором
- **Какие данные или состояние изменяются:** роль пользователя W; B1, B2, ..., Bn стали участниками команды X

## 10. Локальный запуск

**Требования к окружению:** Docker и Docker Compose v2 (например, Docker Desktop), свободный порт 8000. Python и Postgres локально не нужны: всё запускается в контейнерах.

**Команды установки и запуска** (из корня репозитория):

```bash
cp .env.example .env
docker compose up --build
```

При старте контейнер `api` применяет миграции БД (`flask db upgrade` в `run.sh`) и запускает сервер на `http://localhost:8000`. Остановка: `docker compose down` (данные сохраняются в volume `pgdata`; `docker compose down -v` удаляет их).

**Команда или запрос для проверки:**

```bash
curl http://localhost:8000/health
```

**Ожидаемый результат:**

```json
{"status":"ok","db":"ok"}
```

Описание всех endpoints и возможность вызвать их из браузера: Swagger UI по адресу `http://localhost:8000/docs` (спецификация — `app/docs/openapi.yaml`).

Пример основного сценария через API:

```bash
curl -X POST localhost:8000/users -H 'Content-Type: application/json' -d '{"username":"alice"}'
curl -X POST localhost:8000/users -H 'Content-Type: application/json' -d '{"username":"bob"}'
curl -X POST localhost:8000/teams -H 'Content-Type: application/json' -d '{"name":"X","admin_id":1}'
curl -X POST localhost:8000/teams/1/members -H 'Content-Type: application/json' -d '{"user_id":2}'
curl -X POST localhost:8000/teams/1/tasks -H 'Content-Type: application/json' -d '{"title":"Задача Y","author_id":1,"assignee_id":2}'
curl -X PATCH localhost:8000/tasks/1/status -H 'Content-Type: application/json' -d '{"user_id":2,"status":"in_progress"}'
```
