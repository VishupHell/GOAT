# Модель угроз

## Модель продукта

пользователь --> Сервер приложения / API --> БД


**Что уже существует:** Docker образы, модели, некоторые ендпоинты

**Что пока планируется:** Регистрация/вход, создание команды, добавления участников, создание задач


## Границы доверия

| Граница         | Что пересекает | Почему требуется проверка                                                |
|-----------------|----------------|--------------------------------------------------------------------------| 
| Сервер - клиент | Данные         | Потому что клиент может передать какие угодно данные, их нужно проверять |

## Угрозы

| ID | Сценарий угрозы | Что нарушается | Граница / точка входа | Связанные SR | Приоритет и обоснование |
| --- | --- | --- | --- | --- | --- |
| T-01 | Посторонний узнаёт или подбирает ID задачи чужой команды и запрашивает её через API. Без проверки членства он получает описание и статус закрытой задачи. | Конфиденциальность задач команды. | Запрос просмотра задачи по ID через API; граница клиент — сервер. | SR-01 | **Высокий** — раскрытие значимых данных, запрос легко повторять. |
| T-02 | Участник команды подставляет ID задачи, исполнителем которой он не является, и отправляет запрос изменения. Если сервер проверяет только членство в команде, статус или содержимое задачи искажается. | Целостность содержимого и статуса задачи; полномочия исполнителя и администратора. | Запрос изменения задачи через API; граница клиент — сервер. | SR-02 | **Высокий** — затрагивает основной сценарий работы с задачами. |
| T-03 | Обычный участник команды X напрямую отправляет в API запрос создания задачи для команды X. Если сервер проверяет только членство в команде, задача создаётся без решения администратора и попадает в общий список работ. | Полномочия администратора на создание задачи и целостность списка задач команды X. | Запрос создания задачи для команды X через API; граница клиент — сервер. | SR-03 | Средний — искажается список задач команды. |
| T-04 | Клиент без действующей сессии передаёт в запросе создания команды ID зарегистрированного пользователя. Если сервер принимает этот ID за подтверждение входа, команда создаётся от чужого имени. | Подлинность создателя команды и право на создание команды. | Запрос создания команды с `userId` через API; граница клиент — сервер. | SR-04, SR-10 | Средний — подмена создателя команды; актуально для модели входа и API. |
| T-05 | Обычный участник напрямую вызывает метод приглашения в свою команду. Если сервер не проверяет роль администратора, он отправляет приглашение постороннему пользователю без разрешения. | Полномочия администратора на приглашение участников. | Запрос приглашения пользователя через API; граница клиент — сервер. | SR-05 | Средний — неразрешённое изменение круга потенциальных участников. |
| T-06 | Обычный участник отправляет запрос удаления коллеги из команды. Если сервер проверяет лишь членство отправителя, коллега лишается доступа к командной работе. | Состав команды и доступ её участника. | Запрос удаления участника через API; граница клиент — сервер. | SR-06 | **Высокий** — нарушается состав команды и работа исполнителя. |
| T-07 | Обычный участник отправляет запрос удаления задачи по её ID. Если сервер не проверяет роль администратора этой команды, задача исчезает для всех участников. | Целостность и доступность задачи. | Запрос удаления задачи по ID через API; граница клиент — сервер. | SR-07 | Средний — потеря описания и состояния задачи. |
| T-08 | Администратор команды X создаёт задачу и указывает исполнителем пользователя из команды Y. Если API не сверяет исполнителя с составом X, возникает задача с посторонним исполнителем. | Целостность назначения исполнителя и изоляция команд. | Запрос создания задачи с ID исполнителя через API; граница клиент — сервер. | SR-08 | Средний — нарушается целостность распределения задач. |
| T-09 | Администратор удаляет исполнителя из команды, но его прежняя сессия продолжает давать доступ по устаревшим сведениям о членстве. Он читает задачи команды или меняет статус ранее назначенной задачи. | Отзыв доступа, конфиденциальность задач и целостность их статуса. | Запросы чтения и изменения статуса задачи через API после удаления из команды; граница клиент — сервер. | SR-09, SR-01 | **Высокий** — доступ сохраняется после отзыва прав. |
| T-10 | Авторизованный обычный участник передаёт в запросе `role=admin` либо `userId` администратора и пытается удалить другого участника. Если сервер доверяет этим полям, он выполняет действие с чужими правами. | Подлинность полномочий и состав команды. | Запрос удаления участника с полями роли или ID пользователя через API; граница клиент — сервер. | SR-10, SR-06 | **Высокий** — подмена полномочий и изменение состава команды. |
